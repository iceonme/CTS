## 核心洞察

交易策略的参数优化，本质上和深度学习的模型训练**高度同构**。

不同的是，深度学习优化的是神经网络权重，而我们要优化的是"工具/算法/模型的参数"——比如 Grid 策略里的网格层数、枢轴点窗口、买卖间距等。两者的底层逻辑完全一致：**在一个参数空间里，找到能最小化"损失"（最大化"收益"）的最优解**。

---

## 深度学习 vs 策略模型训练：概念对比

| 概念 | 深度学习 | 策略模型训练 |
|------|----------|--------------|
| **模型** | 神经网络权重（浮点数矩阵）| 策略参数（如 `gridLevels`, `pivotN`, `buySpacing`, `windowCount`）|
| **训练数据** | 标注数据集（图片、文本）| 历史 K 线数据（OHLCV）|
| **损失函数** | Cross Entropy / MSE | 综合评分（Sharpe 比率、最大回撤、胜率）|
| **优化器** | SGD / Adam（梯度下降）| 参数搜索算法（随机 → 遗传算法 → 贝叶斯）|
| **验证集** | Holdout Test Set | 样本外时间段（Out-of-Sample）|
| **过拟合** | 训练集好但泛化差 | 历史回测好但实盘失效 |
| **正则化** | Dropout / L2 | 跨时间段验证、多市场验证 |
| **批量训练** | Mini-batch SGD | 并行回测多个参数组合 |
| **早停（Early Stop）**| 验证集 Loss 不再下降 | OOS 评分连续下降则停止进化 |

## 优化目标：如何定义"好的策略"？

> 这是整个体系最关键的设计决策。目标函数（损失函数）的选择直接决定了策略会"进化"成什么样子。

### 候选目标

| 目标 | 优点 | 风险 |
|------|------|------|
| 最大化最终收益率 | 直觉简单 | 容易导致高风险、过拟合 |
| 最大化 Sharpe 比率 | 考虑了风险 | 忽略极端亏损 |
| 最小化最大回撤 | 保护本金 | 可能过于保守，收益少 |
| **综合评分（推荐）** | 均衡多维指标 | 权重设计需要经验 |

### 推荐的综合评分公式

```
score = Sharpe_ratio 
      × (1 - max_drawdown)   // 回撤惩罚
      × win_rate             // 胜率加成
      × trade_count_factor   // 防止"交易一次侥幸赢"的情况
```

## 参数搜索策略（优化器的选择）

按照效率和复杂度递增排列：

### 1. 网格搜索（Grid Search）
- **原理**：穷举所有参数组合的笛卡尔积
- **优点**：简单，覆盖完整
- **缺点**：参数维度高时指数级爆炸（5个参数×10档位 = 10万次回测）
- **适用**：参数少（≤3个）、初步探索阶段

### 2. 随机搜索（Random Search，推荐第一版）
- **原理**：在参数空间中随机采样 N 个组合进行测试
- **优点**：实现极简，效率比网格搜索高（覆盖更广）
- **缺点**：不能利用已有结果做智能引导
- **适用**：第一版快速实现，可在 1-2 天内完成

### 3. 遗传算法（Genetic Algorithm）
- **原理**：模拟生物进化——选择 → 交叉 → 变异
  1. 随机初始化一批"个体"（参数组合）
  2. 评估每个个体的 score
  3. 选择 Top-K 个体作为"父代"
  4. 通过交叉（混合父代参数）和变异（随机修改单个参数）生成下一代
  5. 重复直到收敛
- **优点**：适合大参数空间，天然避免局部最优
- **缺点**：超参数（种群大小、变异率）需要调整
- **适用**：参数空间大（5-20个参数），有一定工程能力后实施

### 4. 贝叶斯优化（Bayesian Optimization，最高效）
- **原理**：建立一个"替代模型"（Surrogate Model）预测参数→评分的映射，每次选择"最有可能更好"的参数组合进行测试
- **优点**：用最少的回测次数找到最优参数，效率最高
- **缺点**：实现复杂，需要引入第三方库（如 `optuna` 或 Python 实现）
- **适用**：成熟阶段，追求高效率

## 防止过拟合：样本内 vs 样本外

> 这是策略训练和真实深度学习最容易忽视的共同点。

### 分段原则
```
全部历史数据
  ├── 训练集（70%）：用于参数搜索/优化
  └── 测试集（30%）：OOS 验证，绝对不能在训练中使用

例：
  训练集：2024-01 ~ 2024-09（牛市 + 中期回调）
  测试集：2024-10 ~ 2024-12（Q4 行情，样本外）
```

### 多市场状态验证
好的参数应该在不同市场状态下都表现稳定：
- **趋势市**：单边上涨/下跌段
- **震荡市**：横盘波动段  
- **高波动市**：黑天鹅/暴涨暴跌段

如果参数只在某一段特别好，大概率是过拟合。

## 快速测试框架设计（工程关键）

> 策略训练的速度瓶颈在于：一次完整回测太慢。要让训练可行，必须先把单次回测速度提升 10-100 倍。

### 加速方案

| 优化点 | 预期加速 | 实现难度 |
|--------|----------|----------|
| 去除 UI 渲染（纯内存计算）| 10-50x | ⭐ 简单 |
| K 线数据只读取一次，复用给所有候选参数 | 2-5x | ⭐ 简单 |
| Node.js Worker Threads 并行化 | N 倍（N=CPU 核数）| ⭐⭐ 中等 |
| 只跑"典型时间窗口"（牛/熊/震荡各一段）| 5-10x | ⭐ 简单 |

### 目标性能指标
- **单次回测**（1年 1m 数据）：< 5 秒（目前未优化版本参考）
- **一轮搜索**（100个参数组合，并行）：< 10 分钟
- **完整训练**（1000个组合 + OOS 验证）：< 1 小时

## 数据保存设计

### 进化日志表结构（建议存入 DuckDB）

```sql
CREATE TABLE evolution_log (
    run_id        VARCHAR,       -- 本次训练的唯一 ID
    run_time      TIMESTAMP,     -- 运行时间
    params        JSON,          -- 参数组合（JSON）
    score         FLOAT,         -- 综合评分
    sharpe        FLOAT,         -- Sharpe 比率
    max_drawdown  FLOAT,         -- 最大回撤
    win_rate      FLOAT,         -- 胜率
    total_return  FLOAT,         -- 总收益率
    trade_count   INTEGER,       -- 交易次数
    period        VARCHAR,       -- 回测时间段（如 "2024-01~2024-09"）
    is_oos        BOOLEAN        -- 是否为样本外验证
);
```

### 可视化需求
- 参数评分散点图（找到高分区域）
- 进化代次 vs 最优评分曲线（观察收敛）
- 不同市场状态下的子评分对比

## 实施路线（参考）

```
第一步：快速回测框架
  → 提取纯内存回测函数，去除 UI 依赖
  → 验证单次回测 < 5s

第二步：随机搜索
  → 定义评分函数
  → 随机采样 100 个参数组合
  → 并行运行，保存结果
  → 输出 Top-5 参数

第三步：样本外验证
  → 对 Top-5 参数在 OOS 时间段验证
  → 对比 IS 和 OOS 评分差距（判断过拟合程度）

第四步：遗传算法
  → 以第二步结果为初始种群
  → 实现选择 → 交叉 → 变异循环
  → 进化 10-20 代

第五步：可视化 & 报告
  → 进化曲线图
  → 最优参数说明书
```

## 延伸思考：进化的不只是参数

当参数优化工作成熟后，可以进一步思考：

1. **工具结构的进化**：不只是参数，而是整个决策逻辑（例如，止损规则是否需要？触发条件是否合理？）
2. **对抗验证**：同一组参数跑多个历史片段，只保留在所有片段都稳定的参数
3. **多策略组合优化**：同时优化 Grid + DCA 的组合比例，找到最优资金分配
4. **在线进化**：根据近期实盘数据持续微调参数（谨慎！容易过拟合近期行情）
